## Critical issues

### C1. The secondary-packaging prompt line can drop real components from the kill-test set
`extractor/prompt.py:64`: "Secondary packaging lines (inner liner, outer box, pallet) are not components unless the sheet gives them a material and describes them as part of the item."
This line goes into the prompt for the **test set** too. The test truth has 10 `outer carton` components (plus 1 in tuning), printed as "outer case"/"outer carton".
- Test sheet **S019** has "Component: outer case … Material n/a … Nett wt 3.425 oz". Its truth is an outer carton with weight 97.1 g and adhesive hot-melt. Read literally, the new line tells the model this is *not* a component, because the sheet gives no material. That loses every slot of the component on the sheet that decides the kill test.
- In UK pEPR, outer and shipment packaging is reportable packaging, so "outer box is not a component" is also the wrong default for the product.
- **Fix:** narrow the line to what the supplement needs. Something like: "Lines listed under a packing/secondary-packaging/palletisation heading that describe how the supplier ships the item (inner liner, outer box, pallet), with no rows of their own, are not components. A component the sheet specifies with its own rows (for example 'Component: outer case') is a component even if some rows are n/a." Add a prompt test for the wording.

### C2. D1 blend rule assigns percentages to the wrong material and accepts quotes joined across cells
`benchmark/taxonomy.py:188-210`. `_PCT_AFTER` is tried before `_PCT_BEFORE`, and the shares are never checked against each other.
- Prefix format with a separator gives the wrong winner: `"70% rPET - 30% PET"` gives `blend_winner` = PET. **rPET (correct) is rejected and PET (wrong) is accepted**, because rPET takes the "- 30%" that belongs to PET, and the tie then goes to PET. `"30% rPET 70% PET"` is right only by luck (tie, then PET).
- Joined cells come back as blends: `"PET 100% | PP 100%"` passes for PET, and `"PET 70% + rPET 30% + HDPE 100%"` passes for **HDPE**. This reopens the one-cell rule for materials whenever cells carry percentages (S803/S804 do).
- **Fix:** (a) choose one orientation for the whole quote. If the first material hit is preceded by a percentage, use "before" for every hit; otherwise use "after". (b) Require the shares to sum to 100 (±1). (c) Optionally restrict D1 to the PET/rPET family, as Amendment 4 says. Add parametrised cases for all of the above.

### C3. S805 "WhiteSolid" scored as colour `missing` turns the business-correct answer into a fabrication
`supplement/data/truth/S805.json`. "WhiteSolid" comes from a real sheet (REALISM row 1). The prompt says "map the sheet's wording to the canonical entry", which invites "white", and a UK compliance user would record white. Under the current truth, "white" with quote "WhiteSolid" is both untraced (no whole-word match) and **fabricated**, the most severe error class. So the slot tests vocabulary literalism, not extraction quality. The other two decisions are fair: "Variable Coloured" → missing, and "Finish: Clear" → clear.
- **Fix (preferred):** truth `white`, quote "WhiteSolid". Accept the wording through a scorer-only alias that `generate.py` does not read. `generate.accepted_for` reads `key_vocab`, so adding the wording to `COLOUR_VOCAB` directly may change the test-set generation; re-run the reproducibility test and the old-vs-new comparison above. **Alternative:** keep the code-only case but print a wording no one would map ("Colour ID W1229", no "WhiteSolid"), so `missing` is plainly right.

## Suggestions

### S1. D2 over-accepts. Anchor the number.
`benchmark/taxonomy.py:214`. The lookahead only checks the next character, so `"Weight (g) 25.5 mm"`, `"Weight (g) 25.5 ml"`, `"Weight (g) 25.5 x 30"`, `"Weight (g) 25.5 gsm"`, `"Gauge (g) 25"` and the joined row `"Height (mm) 120 Weight (g) 25.5"` all pass. Yes, the number should be followed by the end of the quote, optionally with a tolerance (`± …`, `+/- …`), and not by another unit or token. Better still, full-match a single row: `^[a-z .]*\((g|gm|gms|grams|kg|oz)\)\s*(num)(\s*(±|\+/-)\s*num\s*(unit)?)?$` after `norm_quote`. Add the cases above as rejects. The risk is low today (the value must still match within tolerance), but the fix is cheap and keeps traceability strict.

### S2. The other prompt lines are sound
- Blend line: matches D1, and the EXCEPTIONS header resolves the clash with "never include a second material".
- gsm/µm/gauge/case weight → missing: consistent with D3 and the existing "ignore gross/pallet/case weights". No test or tuning component relies on such a weight (test S026's outer case gives "Nett wt" next to "Gross wt per case", so it is unaffected).
- Catalogue line: harmless for the test set, where every sheet names one product code and lists no SKU table.
- Keep these. Record in the amendment that they are now part of the kill-test prompt.

### S3. Budget ordering
NEXT.md says to run the supplement "after tuning (same ledger)". The supplement spends against the same USD 12 / 3M-token caps that the `--set test` preflight checks. If it runs before the test set it can make the test refuse to start. Run it **after** the test set, or have the lead confirm that Q-11 covers it. The supplement has no preflight of its own.

### S4. Truth sample check
I compared truth with the pypdf text for all 12 sheets. Truth is correct:
- S801 tray: 1.36 oz = 38.56 g.
- S802: label units.
- S803: blends, PET and PET-by-tie.
- S804: rPET (PCR 100%) and kraft paper; "Recycling code 1 (PET)" is a fair distractor.
- S806: PB-250-24 = PET/Clear/49.4 g.
- S807: closure "Various …" → missing; secondary lines not components.
- S808: all weights missing.
- S809: features.
- S811: transparent → clear, Doublure n/a → liner missing.
- S812: the AES sheet opens.

Realism nit: S806's distractor weights do not scale with volume (PB-500-38 is 30.2 g, below PB-250-24 at 49.4 g). Harmless, but easy to make plausible.

### S5. Generator side effects
`supplement.seeded_randomness` patches `os.urandom` and `secrets.token_bytes` for the whole process. That is fine in a one-off generator, and it is restored in `finally`. Byte-reproducibility of S812 depends on pypdf's internals, so keep pypdf pinned (it is).

### S6. Truth correctness for S804/S808 names
Component names like "Shipper", "Pouch film" and "Label stock" depend on the model mapping them to the fixed names. That is reasonable given the prompt's mapping instruction, but it is worth a line in Amendment 4.
