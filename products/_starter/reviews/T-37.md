# Review: T-37 per-run test database (branch p/_starter/T-37, head ff77d4f)

Reviewer: reviewer agent, 2026-11-24. Diff: `git diff origin/main...HEAD` (conftest.py, README.md, NEXT.md).

## Verdict: CHANGES

The per-run database works and fixes the T-35 collision. But the stale cleanup drops databases this code did not
create, and the database name goes into SQL unquoted-in-effect, so a crafted `TEST_DATABASE_URL` injects SQL. Both
must be fixed before merge.

## Critical issues

### C1. Stale cleanup drops hand-made databases (conftest.py:43-49)

`^{base}_t(\d+)_\d+_[0-9a-f]+$` accepts any epoch length, any pid, any hex length, and no marker proves this code made
the database. Reproduced: I created `starter_test_t1_1_a` (with `COMMENT ... 'hand made, keep'`), `starter_test_t0_0_0`
and `starter_test_t1700000000_1_deadbeefcafe` by hand; one `pytest tests/test_ai.py` run dropped all three with
`WITH (FORCE)`, killing any open sessions. (`starter_test_t15` and `starter_test_t2026` survive this version's regex,
but the builder's report shows an earlier version dropped `t15`.) Because the base name comes from
`TEST_DATABASE_URL`, pointing it at a real database `app` would drop any `app_t<digits>_<digits>_<hex>` database too.

Fix, all three together:
1. Exact shape: `^{re.escape(base)}_t(\d{10})_(\d{1,7})_([0-9a-f]{6})$` (epoch is 10 digits until 2286, `token_hex(3)` is 6 hex).
2. A marker set at creation, required by cleanup: `COMMENT ON DATABASE <id> IS 'starter-pytest-run v1'` right after
   `CREATE DATABASE`, and in cleanup select `shobj_description(oid, 'pg_database') = 'starter-pytest-run v1'`
   alongside the regex (a fixed tag in the name such as `_pytestrun_` is a cheaper second option; use both if you like).
3. Only consider databases owned by the current user (`datdba = (SELECT oid FROM pg_roles WHERE rolname = current_user)`),
   which also fixes S1 below.

Add a test for `_drop_stale` that creates near-miss names (`<base>_t15`, `<base>_t1_1_a`, a correctly shaped name with
no comment) and asserts they survive, and that a correctly shaped, commented, old one is dropped.

### C2. SQL injection through the database name (conftest.py:49, 63, 72)

Identifiers are wrapped as `"{name}"` with no escaping of `"`. Reproduced: `TEST_DATABASE_URL=.../inj%22%20OWNER%20%22postgres%22%20--`
made the fixture run `CREATE DATABASE "inj" OWNER "postgres" --_t..."`, creating a database `inj` owned by `postgres`
(the suffix commented away, and then leaked). A multi-statement payload is parsed too (it failed only because
CREATE DATABASE cannot run in a transaction block). `_drop_stale` also interpolates names read from `pg_database`.

Fix: build identifiers with `psycopg.sql.Identifier` (on the raw DBAPI connection) or at least `'"' + name.replace('"', '""') + '"'`;
better still, reject a base name that is not `^[A-Za-z0-9_]{1,36}$` with a clear message (36 also keeps the run name
within Postgres's 63-byte limit, see S3).

## Suggestions

- S1 (conftest.py:49): a matching old database owned by another role makes `DROP` raise `must be owner`, and every
  test then errors (reproduced with role `limited`: 88 errors). Filter by owner (C1.3) and wrap each drop in
  try/except with a warning, so cleanup never fails a run.
- S2 (conftest.py:60-63): without CREATEDB the run fails with 88 copies of a raw driver error. Catch
  `InsufficientPrivilege` once and `pytest.exit("... needs CREATEDB; set TEST_DATABASE_SHARED=1 to use the shared DB", 2)`.
  Do not silently fall back to shared: that reintroduces the T-35 wipe without anyone noticing.
- S3 (conftest.py:33): Postgres truncates names over 63 bytes. A base name of 40 chars still passed (2 hex chars cut),
  but over about 47 the pid and random part are cut, so parallel runs can collide and the stale regex stops matching.
  Covered by the length check in C2.
- S4 (conftest.py:60-64): if `Database(TEST_DB)` or anything between CREATE and `try` raises, the new DB leaks. Move
  the `try` to start right after `CREATE DATABASE` succeeds.
- S5: SIGTERM (what a cut-off agent run or timeout sends) skips the finally and leaks the DB until a later run passes
  the 6 h mark. Acceptable with C1 fixed, but a SIGTERM handler that raises KeyboardInterrupt, installed in
  `pytest_configure` would make teardown run. Document `SIGKILL` leaks in README.
- S6 (README.md): the manual cleanup line should also say "only drop names you can see are yours".

## What is good

Per-run isolation is simple and correct for the normal path; `TEST_DATABASE_SHARED=1` keeps the old behaviour;
the finally drops the DB even when tests fail; cleanup never matches the base DB; CI needs no change.
