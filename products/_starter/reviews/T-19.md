## Scope note

The board line for T-19 also lists "GitHub Actions by commit SHA". That part is **not** done. Actions are still on
tags (`actions/checkout@v4` and others). Dependabot will only move tags to new majors; it won't convert them to SHAs.
The deferral is recorded (ADR 0002:334) and tracked as T-30, together with the unpinned `postgres:16` CI service
image. I'm treating that as an accepted split, not a gap in this change. Close T-19 with the scope "base images and
refresh job".

## Suggestions (not blocking)

1. **Node 22 reaches end of life in April 2027**, and the major-version ignore means Dependabot will never propose
   `24-slim`. Node is only used in the build stage, so the risk is low. Still, add a dated board task (for example,
   by March 2027) to move to the next LTS. The same applies to Python 3.12 before October 2028.
2. When the first Dependabot docker PR arrives, check that it is a digest-only refresh of the same tag. That
   confirms the ignores behave as described. It can't be tested from a run.
3. Consider a `groups:` entry so that the two base-image digests (and later, all action bumps) arrive as one weekly PR
   each. That means fewer PRs to review once there are several products.
4. Each product copied from the starter needs its own docker entry (ADR says so). Add a line to the copy checklist in
   `products/README.md` (or the starter README) so it isn't missed.
