### 63 bytes: guaranteed on Linux and macOS

Base is at most 36 ASCII bytes (`^[A-Za-z_][A-Za-z0-9_]{0,35}$`). Suffix: `_t` (2) + epoch (10 digits from 2001 to
2286) + `_` + pid + `_` + `token_hex(3)` (6). Linux `PID_MAX_LIMIT` on 64-bit is 4194304 (7 digits; this host's
`pid_max` is 32768), macOS is 99999. Worst case 36 + 2 + 10 + 1 + 7 + 1 + 6 = 63. Correct, and it matches
`_stale_pattern` (`\d{1,7}`). On Windows a PID is a 32-bit value and could in theory have more digits, and
`_MAX_DB_NAME` is only checked by the test, not at run time (S1).

### Failed-COMMENT drop path

`_create_run_db` drops the DB with `DROP DATABASE IF EXISTS ... WITH (FORCE)` on the same autocommit connection, then
`pytest.exit(..., 2)` with the original error in the message (and as `__context__`). Nothing is left behind when the
drop works. If the drop also fails, a warning is raised, but the exit message still says "it was dropped" (S2). The
original error is not masked. The outer `finally: admin.close()` still runs.

## Critical issues

### C1. Reversed `!==` / `==` / `!=` comparisons are not flagged (tests/test_spa.py:196, alternative `\b(?:!==?|==)\s*path\b`)

`\b` before `!` or `=` only matches when a word character comes right before the operator, so the alternative fires
on `a!==path` but never on `a !== path`. Reproduced with `scan_routes`:

```
'if (x !== path) a();'      -> (set(), [])
'if ("/x" !== path) a();'   -> (set(), [])
'if ("/x" == path) a();'    -> (set(), [])
'if (x != path) a();'       -> (set(), [])
'if (a!==path) a();'        -> (set(), ['!==path'])
```

Why it matters: this is exactly the gap the T-38 change set out to close. A page added as
`if ("/reports" !== path) ...` would not be in `found` and not flagged, so the sync test passes while a refresh on
that page 404s. Fix: replace that alternative with `(?:!==?|(?<![=!])==(?!=))\s*path\b` (just dropping `\b` is
not enough: `==` inside `===` would then flag the readable `"/x" === path`). Checked: it flags `x !== path`,
`"/x" !== path`, `"/x" == path`, `x != path`, and not `"/x" === path` or `x === path`. Then add `'if ("/x" !== path) a();'`
and `'if (x != path) a();'` to the unreadable list in `test_route_scanner_reads_or_flags_the_other_ways_to_write_a_route`.

## Suggestions (non-blocking)

- S1 (conftest.py:42): enforce the limit at run time instead of only in a test:
  `if len(_RUN_NAME.encode()) > _MAX_DB_NAME: pytest.exit(...)` in `database()`, so an unusual platform PID can never
  produce a silently truncated name that the stale cleanup cannot find.
- S2 (conftest.py:102-106): the exit message says "it was dropped" even when the drop failed. Set a flag in the
  `except` and say "could not be dropped; drop it by hand" in that case.
- S3 (conftest.py:101): `except Exception` does not cover `KeyboardInterrupt` (which SIGTERM now raises), so a
  SIGTERM landing between CREATE and COMMENT leaks an unmarked DB. Very narrow window; `except BaseException` with a
  re-raise for non-`Exception` after the drop would close it.
- S4 (test_spa.py scanner): still unflagged, as before this branch: template literals with `${` (`` path === `${B}/x` ``,
  `` `${B}/x` === path ``), `fn("/x") === path`, `path in PAGES`, `PAGES.get(path)`, `matchPath(path, ...)`. Not in
  this task's scope and unlikely in App.tsx today; worth one more alternative (`\bpath\s*===\s*[`(]`, `\)\s*===\s*path`,
  `\bpath\s+in\b`, `\.\s*get\s*\(\s*path\s*\)`) if the router grows.
- S5 (test_testdb_cleanup.py:93-97): `pytest.raises(BaseException)` then comparing `type(...).__name__ == "Exit"` can
  be `pytest.raises(pytest.exit.Exception)`; also assert the DROP comes after the COMMENT (`calls` order).
