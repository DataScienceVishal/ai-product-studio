## Suggestions (not blocking)

1. **`/assets/` still returns 307 when the build has no `assets/` folder.** The mount is skipped (`spa.py:63`), but the
   explicit `/assets` route exists, so Starlette's `redirect_slashes` sends `/assets/` to `/assets` (307), which
   then returns 404. A real Vite build always has `assets/`, so this only shows up with a hand-made dist. Fix: also
   register `/assets/` with `no_asset`, or add the route only inside `if assets.is_dir()`.
2. `POST /assets` now returns a JSON 405 instead of a 404. This is harmless. Register the route for all methods if you want 404.
3. `test_client_routes_fall_back_to_index` lists 10 paths by hand. Parametrising over `sorted(CLIENT_ROUTES)`,
   with GET and HEAD, would make sure every route really returns 200, and not only that the two lists match.
4. The route scanner's `_OTHER` regex allows `X.has(path)` (needed for `PUBLIC.has(path)`). A future
   `ROUTES.has(path) ? <Page/>` would hide a route from the sync test. Leave it, but mention it in the README rule.
5. The README test table says "Backend unit and API tests (205)". The suite now has 238 passed and 1 skipped. Update the count.
6. Unknown paths still render the dashboard or sign-in inside a 404 response, as the docstring says. A small
   not-found view in App.tsx would match what the status code says.
