Repro (`/tmp/claude-0/qa-t128/em`): history.csv `R1,2025-06-07,basic,400.00`; workers.csv `R1,irregular_rolled_up`; leave.csv header only (`worker_id,week_ending`).
Expected: the T-126 headline use (a firm with only rolled-up workers has no look-back leave) runs the rolled-up checks, or FORMAT.md says leave.csv needs a row.
Actual: `leave.csv: no data rows`, exit 2, nothing written. Adding any leave row (even for the rolled-up worker, which is then skipped) makes it run. FORMAT.md and README do not mention this.

### F2 (low) A rolled-up worker with nothing to check is invisible
Repro (`/tmp/claude-0/qa-t128/nop`): R1 `irregular_rolled_up` with only `bonus_non_regular` / `statutory` rows, plus another worker with a leave week.
Expected: some line saying the worker was loaded as rolled-up and had 0 checkable weeks (so a user can tell it was not silently skipped).
Actual: stdout has no second line, report.md has no rolled-up lines at all. Same for a leave.csv row for a rolled-up worker on a week missing from history (`S1,2025-07-05`): counted in the "not re-audited" note only, no `leave_week_missing_from_history` signal.

### F3 (low) BOM inside a cell is echoed in the masked error
Repro: workers.csv data row `W1,variable_hours,<U+FEFF>04-01`.
Expected: an error that says why a visually valid `04-01` is refused.
Actual: `leave_year_start '﻿0...' (6 chars) must be a real calendar date as MM-DD`. The invisible BOM is printed as part of the 2 shown characters and the 6-char length is the only hint. Header-row BOM is handled correctly (file loads).

## Notes (not bugs, behaviour to be aware of)
- A worker switching from variable_hours to irregular_rolled_up mid-history is not modelled: worker_type is one value for the whole history. With `irregular_rolled_up`, the pre-switch weeks (basic, no rolled-up row) all raise `rolled_up_not_shown_separately`, and pre-switch leave weeks are not look-back audited. With `variable_hours`, the post-switch rolled-up rows are warned about and ignored. Documented limitation for leave year start; the type switch is not documented anywhere.
- Part-year rolled-up workers get a "weeks missing from the export" warning for every off-season week.
- A leave.csv row with the optional `weeks` column omitted from one row (ragged row) is refused as "expected 3 fields, found 2". Strict CSV, consistent with other files.
