Verdict: BUGS FOUND (0 high, 2 medium, 4 low). Product code unchanged. Nothing committed. Scratch work in `/tmp/claude-0/t157` (not in the repo). Cases already in reviews/T-147-qa.md are not repeated.

## Evidence
- Full suite, from the product folder: `python3 -I -m unittest discover -s tests -t . -v` gave `Ran 336 tests in 38.630s`, `OK` (0 failures, 0 errors).
- Everything below was run through `python3 -I audit.py` with paths as arguments. Base data: one worker, 60 weeks of basic 100.00, one leave week with holiday_pay.

## Bugs

### B1 (medium) headerless or wrongly headed file prints raw cell values to stderr
Contradicts FORMAT.md line 8 ("Error messages never print a full cell value from any column").
Repro: a history.csv with the header row deleted, so line 1 is `EMP-SECRET-ID-0042,2025-01-04,basic,100.00`; any valid leave.csv.
`python3 -I audit.py --history h.csv --leave l.csv --out out/`
Actual stderr, exit 2:
```
h.csv:1: unexpected column 'EMP-SECRET-ID-0042'
h.csv:1: unexpected column '2025-01-04'
h.csv:1: unexpected column 'basic'
h.csv:1: unexpected column '100.00'
```
The same happens for a headerless leave.csv (`unexpected column 'W1'`, `'2026-02-28'`), and for a header cell such as `John Smith` (not caught by the personal-column check, printed as `unexpected column 'John Smith'`). Cause: `_trunc()` in `ingest/loader.py` shows up to 20 characters of every header cell.
Expected: the first data row's worker_id and amount are never echoed. Apply `_mask()` to header cells that are not in the known column set, or print only a count plus "the file has no header row". Headerless export is one of the most likely user mistakes, so this path is common.

### B2 (medium) an `excluded_week` row in a week that also has counting pay is silently ignored
Repro: base data with `W1,2025-03-15,basic,5000.00` and an added row `W1,2025-03-15,excluded_week,0`. Run with `--include-flagged`.
Actual: exceptions.csv shows average 194.23, byte-identical to the same data without the excluded_week row. The week counts at 5,000.00. There is no flag, no report.md warning and no stderr note. FORMAT.md line 12 says the week is skipped only if it holds no other pay, so this is documented, but nothing tells a user who marked the week and forgot to remove the pay.
Expected: a warning in report.md and on stderr, for example "excluded_week marked on N week(s) that also carry pay that counts; those weeks were NOT skipped" (counts and week dates only, no amounts). The T-154 review (item 8) noted that the name misleads. This is the silent-wrong-average case, which is why it is medium.

### B3 (low) name-like worker_id warnings are capped at 50 with no "and N more", and never reach report.md
`audit.py` slices `name_like_id_warnings(workers)[:MAX_ERRORS_SHOWN]` with no overflow line (code reading). A firm with 200 `first.last` ids sees 50 warnings and no sign of the other 150. The adviser reading report.md sees nothing at all. Verified separately: `john.smith`, `john-smith` and `john_smith` warn; `J.Smith` and `JSmith1990` do not (as documented). Two ids with the same first two characters give identical masked warnings, so the user cannot tell which one triggered it. Suggest an `... and N more` line and one summary sentence in report.md.

### B4 (low) `and K more` wording when the date list is not truncated
When a worker has 10 or fewer runs the text reads `All of them, 2027-03-06, 2027-03-20, ..., 2027-07-10, are in exceptions.csv.` The dates sit between "All of them," and "are in", which reads as if the dates were a subset. Repro: `/tmp/claude-0/t157/cap.py 1 30 0 0 c1` then `tail c1/out/report.md`. Suggest "Their week endings: d1, d2, ... All are in exceptions.csv."

### B5 (low) the leave_year_start error always says "02-29 is not accepted"
Repro: `leave_year_start` = `13-01`, `04-31` or `04/01` gives `must be a real calendar date as MM-DD (for example 01-01 or 04-01); 02-29 is not accepted`. The trailing clause is irrelevant for those values. Cosmetic.

### B6 (low) a non-UTF-8 file gives no line number and no remedy
A Latin-1 `é` in history.csv gives `h.csv: cannot read file: 'utf-8' codec can't decode byte 0xe9 in position 1720: invalid continuation byte`, exit 2. UK payroll exports are often Windows-1252. Suggest "save the file as UTF-8 (CSV UTF-8 in Excel)" and the line number of the first bad byte.

### leave_year_start
`02-29`, `13-01`, `00-10`, `04-31`, `02-30`, `2-1`, `04/01`, `04-1`, `04-01x`, `-04-01` and full-width digits are all refused with a masked message. `12-31`, `01-01` and a blank cell are accepted; ` 04-01 ` with spaces is accepted (trimmed). Wednesday-ending worker with eight leave weeks across 2025-12-31:
- start `12-31`: the week ending 2025-12-31 starts a new year (normal-pay count restarts, as documented).
- start `01-01` and `01-02`: the weeks ending 2025-12-03 to 12-24 are in the old year; 2025-12-31 is the 5th week of that year, so it is basic only; counting restarts at 2026-01-07.
- start `02-28`: the year stays open through January, so 2026-01-07 onward are basic only.
All match the documented rule (week-ending date decides).

### Input robustness
- Accepted as expected: UTF-8 BOM, CRLF, trailing blank lines and `,,,` rows, no final newline, reordered columns, spaces after commas and in headers, quoted cells, a quoted date with an embedded newline (stripped).
- Refused cleanly with exit 2 and nothing written: extra column (`notes`), semicolon or tab delimiters, empty file, header-only history, short row, Devanagari digits, unicode id (`Wé1`), NUL in id, `1.123`, `1.`, `.5`, `1_000`, zero-width space in an amount (message says invisible characters removed), uppercase category, 65-char id, missing file, unwritable `--out`.
- Large amounts: 60 weeks of 999,999,999.99 gives due 999,999,999.99, with correct formatting in both files, and files created 0600.

### CSV and markdown injection
worker_id is the only free-text field that reaches exceptions.csv or report.md. Ids starting `=`, `@`, `+`, `-` or a tab are rejected by the `_ID` regex before any output is written, so `_safe()` is defence in depth and cannot be triggered. An id of `W_1_x_.a-b` is written to report.md as `W\_1\_x\_.a\-b` (escaped) and as itself in exceptions.csv. No injection path found.

- Not in scope and unchanged: engine maths, caps (consistent), masking (clean except B1), leave_year_start (correct).
