## Observations (not bugs, no action needed)
- O1 (low, engine only): `lookback()` called directly with fixed_pay silently ignores a negative basic line. variable_hours raises `negative weekly pay`. The CLI rejects negatives before they reach the engine, so unreachable by users.
- O2 (low, design, already known as T136-F2): the ambiguity flag looks only at the 8-week window. A stale rate with weeks 1-7 empty and an older different basic at week 9+ is not flagged ambiguous. Matches the documented rule "most recent basic in the last 8 weeks".
- O3 (low, doc): rolled-up pay base uses `normal_pay` (excludes non-regular bonus and SSP). This is a defensible reading and is pinned by tests. An adviser should confirm it.
